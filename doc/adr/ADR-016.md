# ADR-016: Privacidade de Dados de Usuário e Conformidade (LGPD)

- **Status:** Proposto
- **Data:** 2026-09-14
- **Decisores:** [Seu Nome / Equipe]
- **Contexto Técnico:** Classificação de dados pessoais, direitos do titular e medidas de conformidade com a LGPD
- **Tags:** `privacidade`, `lgpd`, `dados-pessoais`, `conformidade`, `segurança`, `transversal`
- **Depende de:** ADR-001 (Plataforma), ADR-002 (Máscara — segredos de campanha), ADR-013 (IA), ADR-015 (Autenticação), ADR-014 (Escopo do MVP)
- **Tipo:** ADR Transversal — **bloqueante para o MVP** (ADR-014, seção 2.4)

---

## 1. Contexto

Os ADR-002 e ADR-009 já definem um sistema de "Segredos" e níveis de visibilidade (Público/Privado/Secreto), mas isso trata de **informação narrativa da crônica** (ex.: quem sabe que um NPC é um diablerista) — não de **dados pessoais reais** dos usuários (e-mail, identificador OAuth, endereço IP, conteúdo que o usuário escreve sobre si mesmo em fichas/diários). Este ADR trata exclusivamente da segunda categoria, e é **pré-requisito para produção**, já que a plataforma opera no Brasil e está sujeita à Lei Geral de Proteção de Dados (Lei 13.709/2018).

É importante não confundir os dois sistemas: um jogador pode ter total controle sobre os "segredos" do seu personagem na ficção, mas isso não substitui os direitos legais que ele tem sobre seus **próprios dados pessoais reais** como titular.

---

## 2. Decisão

### 2.1. Classificação de Dados Pessoais Coletados

**Decisão:** Classificar explicitamente todo dado pessoal coletado pela plataforma, distinguindo-o de conteúdo de ficção.

| Categoria | Dados | Base Legal (LGPD) | Retenção |
|-----------|-------|---------------------|----------|
| **Cadastro** | E-mail, nome de exibição, id do provedor OAuth, avatar | Execução de contrato (Art. 7º, V) | Enquanto a conta existir |
| **Autenticação** | Hash de senha, tokens de sessão, IP e user agent de login | Execução de contrato / legítimo interesse de segurança (Art. 7º, IX) | 90 dias (logs), enquanto ativo (sessões) |
| **Uso da plataforma** | Logs de acesso, eventos de auditoria (ADR-015) | Legítimo interesse de segurança | 180 dias |
| **Conteúdo gerado pelo usuário** | Fichas de personagem, mensagens de chat, diário do personagem | Execução de contrato | Enquanto a conta/crônica existir |
| **Dados de pagamento (futuro)** | Não armazenados diretamente — processados por gateway terceirizado (ex.: Stripe) | Execução de contrato | Conforme política do gateway |
| **Dados enviados a IA (ADR-013, opcional)** | Prompts e contexto autorizado pelo Narrador | Consentimento explícito (opt-in por caso de uso) | Não retido pelo provedor de IA (ver ADR-013, §2.6) |

**Nota:** Conteúdo de ficção (nome de personagem, segredos de campanha, tramas) **não é dado pessoal do titular real** a menos que o usuário insira dados pessoais de terceiros nesse conteúdo (ex.: usar o nome real de outra pessoa) — isso é tratado como risco de uso indevido pelo próprio usuário, não como coleta pela plataforma.

### 2.2. Direitos do Titular

**Decisão:** Implementar os direitos do Art. 18 da LGPD via funcionalidades de autoatendimento, sem exigir contato manual com suporte para os casos mais comuns.

| Direito | Implementação |
|---------|----------------|
| **Confirmação e acesso** | Tela "Meus Dados" mostra todos os dados pessoais armazenados. |
| **Exportação (portabilidade)** | Botão "Exportar Meus Dados" gera um JSON com cadastro, personagens e conteúdo gerado pelo usuário. |
| **Correção** | Edição direta de perfil (nome, e-mail, avatar). |
| **Eliminação / Revogação de consentimento** | Botão "Excluir Minha Conta" — ver fluxo de exclusão (2.3). |
| **Informação sobre compartilhamento** | Página de privacidade lista todos os operadores terceiros (2.4). |
| **Oposição** | Usuário pode desativar recursos opcionais que processam mais dados (ex.: IA) a qualquer momento. |

**Estrutura de Dados:**

```
SolicitaçãoExclusão (DeletionRequest)
├── id: UUID
├── usuário: UUID
├── solicitado_em: datetime
├── executar_em: datetime        # solicitado_em + 30 dias (janela de arrependimento)
├── status: enum                 # Pendente | Cancelada | Executada
└── escopo: enum                 # Conta Completa | Apenas Dados Pessoais (mantém personagens anonimizados)
```

### 2.3. Fluxo de Exclusão de Conta

**Decisão:** Exclusão em duas etapas — **anonimização imediata dos dados de identificação** + **janela de 30 dias** antes da remoção definitiva, para permitir arrependimento e para não quebrar crônicas de outros jogadores.

1. Usuário solicita exclusão → conta é marcada como "Em exclusão", login é bloqueado.
2. Dados de identificação (e-mail, id OAuth, avatar) são imediatamente anonimizados.
3. Personagens e mensagens em crônicas **compartilhadas com outros jogadores** são mantidos, mas com autoria exibida como "Usuário Removido" — remover o conteúdo completamente quebraria a crônica de terceiros que não solicitaram exclusão.
4. Após 30 dias, os dados remanescentes ligados exclusivamente ao usuário (histórico de login, tokens, preferências) são apagados em definitivo.
5. Backups de banco de dados seguem sua própria política de retenção/expurgo (ver ADR-018) — a exclusão não pode ser instantânea em backups já feitos, o que é comunicado explicitamente na política de privacidade.

### 2.4. Operadores de Dados Terceiros

**Decisão:** Listar e formalizar (contratualmente, quando aplicável) todo terceiro que processa dados pessoais dos usuários.

| Operador | Dado Processado | Finalidade |
|----------|-------------------|------------|
| **Discord / Google (OAuth)** | Id, e-mail, nome, avatar | Autenticação |
| **Provedor de hospedagem (ADR-018)** | Todos os dados armazenados | Infraestrutura |
| **Provedor de IA (ADR-013, opcional e opt-in)** | Contexto de prompt autorizado pelo Narrador | Funcionalidades de IA |
| **Ferramenta de rastreamento de erros (ex.: Sentry)** | Stack traces, metadados de requisição (sem dados sensíveis quando possível) | Observabilidade (ADR-018) |
| **Gateway de pagamento (futuro)** | Dados de pagamento | Cobrança |

Cada operador precisa de uma cláusula de **não retenção para treinamento de modelos** quando aplicável (já exigido no ADR-013, princípio 4) e de um Acordo de Processamento de Dados (DPA) equivalente antes de entrar em produção.

### 2.5. Consentimento e Idade Mínima

**Decisão:**
- Consentimento explícito e granular para funcionalidades opcionais que processam dados adicionais (IA, cookies não essenciais).
- Declaração de idade mínima de **16 anos** no cadastro (conteúdo do jogo é temático adulto — violência, horror, temas morais complexos — alinhado ao Art. 14 da LGPD, que trata tratamento de dados de crianças/adolescentes).
- Cookies: apenas essenciais (sessão) por padrão; qualquer analytics é opt-in explícito, nunca ativado por padrão.

### 2.6. Segurança dos Dados

| Medida | Descrição |
|--------|-----------|
| **Criptografia em trânsito** | TLS 1.3 obrigatório em toda comunicação (HTTP e WebSocket). |
| **Criptografia em repouso** | Disco do banco de dados criptografado (recurso do provedor de hospedagem). |
| **Minimização** | Apenas os campos estritamente necessários são coletados; nenhum dado "por precaução". |
| **Controle de acesso** | Acesso de equipe ao banco de produção restrito e auditado (ligado ao papel `Moderador` do ADR-015). |
| **Plano de resposta a incidentes** | Processo documentado de notificação à ANPD e aos titulares em caso de vazamento (Art. 48 da LGPD), com prazo definido (comunicação "em prazo razoável"). |

### 2.7. Encarregado de Dados (DPO)

**Decisão:** Para o MVP, o papel de Encarregado (Art. 41) é assumido pelo(a) responsável técnico do projeto, com um canal de contato público (e-mail dedicado) listado na política de privacidade. Formalização de um DPO dedicado é revisitada quando a base de usuários crescer.

## 3. Consequências

### 3.1. Positivas
- Conformidade legal desde o lançamento evita risco de multa (até 2% do faturamento, limitado a R$ 50 milhões por infração) e de embargo da operação no Brasil.
- Separar claramente "dados pessoais reais" de "segredos de ficção" evita confusão de modelo (um Narrador não pode usar "autoridade narrativa" para justificar acesso indevido a dados pessoais de jogadores).
- Anonimização em vez de exclusão total de conteúdo compartilhado preserva a experiência de outros usuários sem violar o direito de exclusão do titular.

### 3.2. Negativas
- Fluxo de exclusão em duas etapas (30 dias) adiciona complexidade de estado e um job agendado para execução definitiva.
- Exportação de dados e anonimização em cascata exigem consultas específicas em todas as tabelas que referenciam o usuário — precisa ser mantido atualizado conforme o schema evolui.
- Qualquer novo operador terceiro (nova integração) exige revisão deste ADR e do DPA correspondente.

### 3.3. Alternativas Descartadas

| Alternativa | Motivo da Rejeição |
|-------------|---------------------|
| **Exclusão imediata e total, incluindo conteúdo compartilhado** | Quebraria crônicas de outros usuários que não solicitaram exclusão; desproporcional ao direito do titular, que é sobre seus dados pessoais, não sobre apagar a experiência de terceiros. |
| **Tratar segredos de campanha como dado pessoal sujeito à LGPD** | Confundiria mecânica de jogo com direito real; segredos de ficção não identificam uma pessoa natural real. |
| **Sem janela de arrependimento na exclusão** | Aumentaria solicitações irreversíveis por engano, gerando suporte e insatisfação. |
| **DPO terceirizado desde o MVP** | Custo desnecessário antes de haver escala de usuários que justifique. |
