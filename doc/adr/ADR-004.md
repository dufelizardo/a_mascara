# ADR-004: Modelo de Dados da Ficha de Personagem

- **Status:** Proposto
- **Data:** 2026-09-14
- **Decisores:** [Seu Nome / Equipe]
- **Contexto Técnico:** Modelagem da estrutura de dados da ficha de personagem
- **Tags:** `ficha`, `personagem`, `atributos`, `habilidades`, `vantagens`, `virtudes`, `criação-de-personagem`, `vampiro-a-mascara`
- **Depende de:** ADR-001 (Plataforma e Arquitetura Geral), ADR-002 (Modelagem do Mundo das Trevas), ADR-003 (Modelagem de Clãs, Seitas e Estrutura Política)

---

## 1. Contexto

O **Capítulo Três: Personagens e Características** é o guia definitivo para a criação e o gerenciamento de personagens em _Vampiro: A Máscara_. Ele define **todos os atributos, habilidades e características** que compõem um personagem, desde a sua concepção até a sua evolução ao longo da crônica.

A ficha de personagem é o **objeto de dados mais importante** da plataforma. Ela precisa:

- Ser **completa**, contendo todos os dados do Capítulo Três.
- Ser **interativa**, permitindo que o jogador gerencie seu personagem.
- Ser **reativa**, aplicando automaticamente as regras (Fraquezas de Clã, Disciplinas, Humanidade, etc.).
- Ser **colaborativa**, permitindo que o Narrador e outros jogadores vejam (o que for permitido) a ficha.
- Ser **persistente**, salvando o estado do personagem entre sessões.
- Ser **versionada**, registrando a evolução do personagem ao longo do tempo.

Este ADR define **como modelar a ficha de personagem** na plataforma, estabelecendo as bases para os motores de Disciplinas (ADR-005), Resolução de Ações (ADR-006), Sistemas Dramáticos (ADR-007) e Moralidade (ADR-008).

---

## 2. Decisão

Decidimos modelar a ficha de personagem como uma **entidade de dados rica e hierárquica**, com **oito seções fundamentais**, cada uma representando um aspecto do Capítulo Três.

### 2.1. Estrutura Geral da Ficha de Personagem

**Decisão:** A ficha de personagem é modelada como um **documento JSONB armazenado no PostgreSQL** (ver 2.12) — não um banco NoSQL separado —, com a seguinte estrutura de alto nível:
```

Personagem (Character)
├── id: UUID
├── meta: Meta # Informações básicas
├── atributos: Atributos # Físico, Social, Mental
├── habilidades: Habilidades # Talentos, Perícias, Conhecimentos
├── vantagens: Vantagens # Disciplinas, Antecedentes, Virtudes
├── estado: Estado # Humanidade, Força de Vontade, Vitalidade, Sangue
├── identidade: Identidade # Natureza, Comportamento, Conceito, Clã, Geração
├── histórico: Histórico # Prelúdio, Evolução, Experiência
└── meta_jogo: MetaJogo # Referências a Campanhas, Sessões, Notas

```

### 2.2. Seção 2.2: Meta (Informações Básicas)

**Decisão:** A seção `meta` contém as informações administrativas e de identificação do personagem.

```

Meta
├── nome: string # Nome do personagem
├── jogador: UUID # Referência ao usuário que controla o personagem
├── crônica: UUID # Referência à crônica à qual pertence
├── criado_em: datetime # Data de criação
├── atualizado_em: datetime # Última atualização
├── avatar: URL # Imagem do personagem
├── status: enum # Ativo | Inativo | Morto | Torpor
└── visibilidade: enum # Público | Privado | Secreto (ver ADR-002)

```

### 2.3. Seção 2.3: Atributos

**Decisão:** Modelar os **nove Atributos** divididos em três categorias (Físico, Social, Mental), com valores de 1 a 5 (podendo chegar a 10 para anciões).

**Estrutura de Dados:**

```

Atributos
├── fisico: Físico
│ ├── forca: int # Força (1-5+)
│ ├── destreza: int # Destreza (1-5+)
│ └── vigor: int # Vigor (1-5+)
├── social: Social
│ ├── carisma: int # Carisma (1-5+)
│ ├── manipulacao: int # Manipulação (1-5+)
│ └── aparencia: int # Aparência (0-5+)
└── mental: Mental
├── percepcao: int # Percepção (1-5+)
├── inteligencia: int # Inteligência (1-5+)
└── raciocinio: int # Raciocínio (1-5+)

```

**Regras Automáticas:**

- **Custo de Evolução:** O custo para aumentar um Atributo é `nível atual × 4` pontos de experiência (ver ADR-006).
- **Limite de Geração:** O valor máximo de um Atributo é determinado pela Geração do personagem (ver tabela em ADR-003).
- **Aumento Temporário:** O jogador pode gastar pontos de sangue para aumentar temporariamente um Atributo Físico (ver ADR-007).
- **Especialidades:** Personagens com Atributos 4+ podem escolher Especialidades (ex: Força → "Mãos Fortes").

**Tabela de Especialidades (Exemplos):**

| Atributo | Especialidades Sugeridas |
|----------|--------------------------|
| Força | Mãos Fortes, Braços Poderosos, Reservas de Força, Punhos de Ferro |
| Destreza | Flexibilidade, Velocidade, Movimentos Felinos, Reflexos Rápidos |
| Vigor | Incansável, Determinado, Resistente, Vigoroso |
| Carisma | Fala Mansa, Distinto, Urbano, Engraçado, Eloquente |
| Manipulação | Convincente, Sedutor, Bom Argumentador |
| Aparência | Fotogênico, Rosto Inesquecível, Pose Memorável |
| Percepção | Atento, Introspectivo, Cuidadoso, Penetrante |
| Inteligência | Literato, Criativo, Analítico, Solucionador de Problemas |
| Raciocínio | Ganhar a Dianteira, Orador Vigoroso, Mudar de Estratégia |

### 2.5. Seção 2.5: Vantagens

**Decisão:** Modelar as **Vantagens** como três subcategorias: Disciplinas, Antecedentes e Virtudes.

#### 2.5.1. Disciplinas

**Estrutura de Dados:**

```

Disciplinas
├── animalismo: int # Nível (0-5+)
├── auspicios: int
├── demencia: int
├── dominacao: int
├── fortitude: int
├── metamorfose: int
├── necromancia: int
├── ofuscacao: int
├── potencia: int
├── presenca: int
├── quietus: int
├── quimerismo: int
├── rapidez: int
├── serpentis: int
├── taumaturgia: int
├── tenebrosidade: int
└── vicissitude: int

```

**Regras Automáticas:**

- **Disciplinas de Clã:** O personagem começa com 3 pontos para distribuir entre as Disciplinas do seu Clã (ver ADR-003).
- **Disciplinas Fora do Clã:** O personagem pode aprender Disciplinas de outros Clãs, mas com custo maior (ver ADR-006).
- **Poderes de Nível 6+:** Apenas personagens de Geração 7 ou inferior podem ter Disciplinas acima de 5 (ver ADR-003).
- **Custo de Sangue:** Alguns poderes de Disciplina requerem o gasto de pontos de sangue (ver ADR-005).

#### 2.5.2. Antecedentes

**Estrutura de Dados:**

```

Antecedentes
├── aliados: int # Aliados mortais
├── contatos: int # Rede de contatos
├── dominio: int # Território de caça
├── fama: int # Fama entre os mortais
├── geracao: int # Geração (Background)
├── influencia: int # Influência política mortal
├── identidade_alternativa: int # Identidade falsa
├── lacaios: int # Servos (carniçais, etc.)
├── mao_negra: int # Membros da Mão Negra (Sabá)
├── mentor: int # Mentor vampiro
├── rebanho: int # Fontes de sangue seguras
├── recursos: int # Riqueza
├── rituais: int # Conhecimento de ritae (Sabá)
└── status: int # Posição na sociedade vampírica

```

**Regras Automáticas:**

- **Pontos Iniciais:** O personagem começa com 5 pontos para distribuir entre os Antecedentes.
- **Geração:** O Antecedente Geração determina a Geração do personagem (ver tabela em ADR-003).
- **Status:** O Antecedente Status determina a posição inicial do personagem na hierarquia (ver ADR-003).
- **Antecedentes Combinados:** Personagens de um mesmo círculo podem combinar Antecedentes (ver p. 118 do livro).

#### 2.5.3. Virtudes

**Estrutura de Dados:**

```

Virtudes
├── consciencia: int # Consciência (1-5)
├── autocontrole: int # Autocontrole (1-5)
├── coragem: int # Coragem (1-5)
├── conviccao: int # Convicção (alternativa, 0-5)
└── instinto: int # Instinto (alternativa, 0-5)

```

**Regras Automáticas:**

- **Pontos Iniciais:** O personagem começa com 1 ponto em Consciência e 1 em Autocontrole, e 1 em Coragem, mais 7 pontos para distribuir.
- **Virtudes Alternativas:** Personagens que seguem Trilhas da Sabedoria podem usar Convicção e Instinto (ver ADR-008).
- **Humanidade:** A Humanidade inicial é igual a `Consciência + Autocontrole` (ver ADR-008).
- **Força de Vontade:** A Força de Vontade inicial é igual a `Coragem` (ver ADR-008).
- **Testes de Virtude:** As Virtudes são usadas em testes de frenesi, degeneração, etc. (ver ADR-007 e ADR-008).

### 2.6. Seção 2.6: Estado (Características Dinâmicas)

**Decisão:** Modelar o **estado atual** do personagem, que muda durante o jogo.

```

Estado
├── humanidade: int # 0-10 (ou Trilha da Sabedoria)
├── forca_vontade: ForçaVontade
│ ├── permanente: int # 1-10
│ └── atual: int # 0-permanente
├── vitalidade: Vitalidade
│ ├── escoriado: bool
│ ├── machucado: bool
│ ├── ferido: bool
│ ├── ferido_gravemente: bool
│ ├── espancado: bool
│ ├── aleijado: bool
│ └── incapacitado: bool
├── pontos_sangue: int # 0-máximo (ver Geração)
├── pontos_sangue_por_turno: int # Máximo gasto por turno
├── experiencia: int # Pontos de experiência
├── experiencia_gasta: int # Pontos de experiência gastos
└── status_efeitos: [Efeito] # Efeitos ativos (frenesi, laço de sangue, etc.)

```

**Regras Automáticas:**

- **Humanidade:** Diminui com atos transgressores (ver ADR-008). Se chegar a 0, o personagem é controlado pelo Narrador.
- **Força de Vontade:** Pode ser gasta para obter sucessos automáticos, resistir a Dominação, etc. (ver ADR-006).
- **Vitalidade:** Diminui com dano (ver ADR-007). Penalidades são aplicadas automaticamente.
- **Pontos de Sangue:** Diminuem 1 por noite, e podem ser gastos para curar, aumentar Atributos, ativar Disciplinas, etc. (ver ADR-007).
- **Experiência:** Ganha ao final de cada sessão (ver ADR-006). Gasta para evoluir características.

**Tabela de Vitalidade:**

| Nível | Penalidade | Penalidade de Movimento |
|-------|------------|-------------------------|
| Escoriado | 0 | Nenhuma |
| Machucado | -1 | Nenhuma |
| Ferido | -1 | Metade da velocidade máxima de corrida |
| Ferido Gravemente | -2 | Não pode correr |
| Espancado | -2 | Só pode mancar (3m/turno) |
| Aleijado | -5 | Só pode rastejar (1m/turno) |
| Incapacitado | - | Não pode se mover |
| Torpor | - | Estado de morte aparente |
| Morte Final | - | Personagem destruído |

**Tabela de Pontos de Sangue por Geração:**

| Geração | Máx. Pontos de Sangue | Pontos por Turno |
|---------|----------------------|------------------|
| 13ª+ | 10 | 1 |
| 12ª | 11 | 1 |
| 11ª | 12 | 1 |
| 10ª | 13 | 1 |
| 9ª | 14 | 2 |
| 8ª | 15 | 3 |
| 7ª | 20 | 4 |
| 6ª | 30 | 6 |
| 5ª | 40 | 8 |
| 4ª | 50 | 10 |

### 2.7. Seção 2.7: Identidade (Natureza, Comportamento, Conceito)

**Decisão:** Modelar a **identidade narrativa** do personagem.

```

Identidade
├── conceito: string # Ex: "Detetive Particular"
├── cla: UUID # Referência ao Clã (ver ADR-003)
├── seita: UUID # Referência à Seita (ver ADR-003)
├── geracao: int # Número da Geração (ex: 13)
├── senhor: UUID # Referência ao senhor (se conhecido)
├── natureza: Arquétipo # Arquétipo da Natureza
├── comportamento: Arquétipo # Arquétipo do Comportamento
├── trilha: UUID # Trilha da Sabedoria (se aplicável)
└── preludio: text # História do personagem antes do Abraço

```

**Regras Automáticas:**

- **Natureza:** Usada para recuperar Força de Vontade quando o personagem age de acordo com ela (ver ADR-006).
- **Comportamento:** A "máscara" que o personagem apresenta ao mundo.
- **Clã e Seita:** Determinam Disciplinas, Fraquezas e Status (ver ADR-003).
- **Trilha:** Se o personagem segue uma Trilha da Sabedoria, substitui a Humanidade (ver ADR-008).

### 2.8. Seção 2.8: Histórico (Prelúdio, Evolução, Experiência)

**Decisão:** Modelar o **histórico narrativo** e a **evolução** do personagem.

```

Histórico
├── preludio: text # História antes do Abraço
├── abraco: Abraço # Detalhes do Abraço
│ ├── data: datetime
│ ├── senhor: UUID
│ ├── local: string
│ └── circunstâncias: text
├── diario: [EntradaDiario] # Diário do personagem
│ ├── data: datetime
│ ├── título: string
│ └── conteúdo: text
├── evolucao: [EventoEvolucao] # Marcos da não-vida
│ ├── data: datetime
│ ├── tipo: enum # Título | Diablerie | Golconda | etc.
│ └── descrição: text
└── experiência: Experiência # Histórico de ganho/gasto de XP
├── total_ganho: int
├── total_gasto: int
└── log: [EntradaXP]

```

**Funcionalidades:**

- **Prelúdio:** O jogador escreve a história do personagem antes do Abraço. O Narrador pode usar isso para criar ganchos narrativos.
- **Diário:** O jogador pode manter um diário do personagem, registrando seus pensamentos e experiências.
- **Evolução:** A plataforma registra automaticamente marcos importantes (ex: "Tornou-se Ancillae", "Cometeu Diablerie", "Atingiu Golconda").
- **Experiência:** A plataforma rastreia o ganho e gasto de pontos de experiência, com um log detalhado.

### 2.9. Seção 2.9: MetaJogo (Referências Externas)

**Decisão:** Modelar as **referências externas** ao personagem.

```

MetaJogo
├── campanhas: [UUID] # Campanhas das quais o personagem participou
├── sessões: [UUID] # Sessões das quais o personagem participou
├── notas: [Nota] # Notas do jogador
├── segredos: [Segredo] # Segredos do personagem (visíveis apenas ao Narrador)
├── objetivos: [Objetivo] # Objetivos pessoais do personagem
└── relacionamentos: [Relacionamento] # Relações com outros personagens (PCs e NPCs)

```

**Funcionalidades:**

- **Relacionamentos:** A plataforma modela as relações do personagem com outros (Aliado, Rival, Inimigo, Laço de Sangue, etc.) — ver ADR-003.
- **Objetivos:** O jogador define objetivos de curto, médio e longo prazo para o personagem.
- **Segredos:** O Narrador pode registrar segredos sobre o personagem (ex: "Ele é um diablerista"), visíveis apenas a ele.

### 2.10. Processo de Criação de Personagem

**Decisão:** Implementar o **processo de criação de personagem** como um **assistente passo a passo**, com validação automática.

**Fluxo de Criação:**

```

1. Conceito do Personagem
   ├── Nome, Conceito, Crônica
   └── Prelúdio (opcional)

2. Escolha de Clã e Seita
   ├── Clã (ver ADR-003)
   ├── Seita (ver ADR-003)
   └── Geração (ver ADR-003)

3. Escolha de Natureza e Comportamento
   └── Arquétipos (ver 2.7)

4. Distribuição de Atributos
   ├── Priorizar categorias (7/5/3)
   ├── Distribuir pontos
   └── Escolher Especialidades (se aplicável)

5. Distribuição de Habilidades
   ├── Priorizar categorias (13/9/5)
   ├── Distribuir pontos
   └── Escolher Especialidades (se aplicável)

6. Escolha de Vantagens
   ├── Disciplinas (3 pontos)
   ├── Antecedentes (5 pontos)
   └── Virtudes (7 pontos + 1 em Consciência e Autocontrole)

7. Toques Finais
   ├── Humanidade = Consciência + Autocontrole
   ├── Força de Vontade = Coragem
   ├── Pontos de Sangue = rolar 1d10
   └── Gastar Pontos Bônus (15)

8. Qualidades e Defeitos (Opcional)
   ├── Escolher Qualidades (gastam pontos bônus)
   └── Escolher Defeitos (ganham pontos bônus, máx. 7)

9. Revisão e Aprovação
   ├── Preview da ficha completa
   └── Aprovação do Narrador

````

**Funcionalidades:**

- **Validação Automática:** A plataforma impede distribuições inválidas (ex: mais de 3 pontos em uma Habilidade na criação).
- **Cálculo Automático:** A plataforma calcula automaticamente Humanidade, Força de Vontade e Pontos de Sangue.
- **Sugestões:** A plataforma sugere Arquétipos, Antecedentes e Disciplinas com base no Clã e Seita.
- **Preview:** O jogador vê uma prévia da ficha antes de confirmar.
- **Aprovação:** O Narrador pode revisar e aprovar (ou pedir alterações).

### 2.11. Evolução do Personagem

**Decisão:** A ficha de personagem é **viva e evolutiva**, mudando ao longo da crônica.

**Mecânicas de Evolução:**

- **Ganho de Experiência:** Ao final de cada sessão, o Narrador concede pontos de experiência (ver ADR-006).
- **Gasto de Experiência:** O jogador gasta pontos para evoluir Atributos, Habilidades, Disciplinas, Virtudes, Humanidade/Trilha e Força de Vontade (ver ADR-006).
- **Mudanças de Estado:** Humanidade, Força de Vontade, Vitalidade e Pontos de Sangue mudam durante o jogo.
- **Marcos Narrativos:** A plataforma registra marcos (ex: "Tornou-se Ancillae", "Aprendeu uma nova Disciplina").
- **Versionamento:** A plataforma mantém um histórico de todas as mudanças na ficha.

**Tabela de Custo de Experiência:**

| Característica | Custo |
|----------------|-------|
| Nova Habilidade | 3 |
| Nova Disciplina | 10 |
| Novo Caminho (Necromancia/Taumaturgia) | 7 |
| Atributo | nível atual × 4 |
| Habilidade | nível atual × 2 |
| Disciplina de Clã | nível atual × 5 |
| Outras Disciplinas | nível atual × 7 |
| Caminho Secundário | nível atual × 4 |
| Virtude | nível atual × 2 |
| Humanidade/Trilha | nível atual × 2 |
| Força de Vontade | nível atual |

### 2.12. Armazenamento e Sincronização

**Decisão:** A ficha de personagem é armazenada no **banco de dados principal** (PostgreSQL) e sincronizada em **tempo real** (WebSockets) com todos os clientes autorizados.

**Estratégia:**

- **Banco de Dados:** A ficha é armazenada como um documento JSONB no PostgreSQL, permitindo consultas flexíveis.
- **Cache:** A ficha é cacheada no Redis para acesso rápido.
- **Sincronização:** Quando um jogador altera a ficha, a mudança é enviada via WebSocket para o Narrador e outros jogadores (conforme permissão — ver ADR-015).
- **Versionamento:** Cada seção da ficha carrega um número de versão (ver 2.13); o histórico registra apenas a seção alterada e sua versão, não o documento inteiro — ver justificativa em 2.13.
- **Backup:** A ficha é incluída nos backups automáticos do banco de dados (ver ADR-018).

**Exemplo de Estrutura no PostgreSQL:**

```sql
CREATE TABLE personagens (
    id UUID PRIMARY KEY,
    nome VARCHAR(255) NOT NULL,
    jogador_id UUID REFERENCES usuarios(id),
    cronica_id UUID REFERENCES cronicas(id),
    dados JSONB NOT NULL,       -- Ficha completa em JSON
    versoes JSONB NOT NULL,     -- {"atributos": 3, "habilidades": 1, "vantagens": 5, "estado": 12, ...} — ver 2.13
    criado_em TIMESTAMP DEFAULT NOW(),
    atualizado_em TIMESTAMP DEFAULT NOW()
);

CREATE TABLE personagens_historico (
    id SERIAL PRIMARY KEY,
    personagem_id UUID REFERENCES personagens(id),
    secao VARCHAR(50) NOT NULL,   -- ex.: "atributos", "estado" — apenas a seção alterada, não o documento inteiro
    versao INT NOT NULL,
    dados_secao JSONB NOT NULL,   -- conteúdo da seção após a alteração, não a ficha inteira
    alterado_em TIMESTAMP DEFAULT NOW(),
    alterado_por UUID REFERENCES usuarios(id)
);
```

### 2.13. Resolução de Conflitos de Edição Concorrente

**Contexto da decisão:** a ficha é editada por mais de uma pessoa ao mesmo tempo — tipicamente o Jogador dono do personagem e o Narrador (ex.: o Narrador ajusta a Humanidade enquanto o Jogador distribui pontos de Habilidade). Sem uma estratégia explícita, uma escrita pode sobrescrever silenciosamente a outra (last-write-wins não avisado), perdendo dados sem que ninguém perceba — o risco identificado na revisão arquitetural do conjunto de ADRs e exigido como pré-requisito de teste pelo ADR-017 (§2.3).

**Decisão:** **Controle de concorrência otimista (OCC) no nível de seção**, não no documento inteiro e não via CRDT/Operational Transformation.

**Como funciona:**

1. Cada uma das 8 seções da ficha (`meta`, `atributos`, `habilidades`, `vantagens`, `estado`, `identidade`, `histórico`, `meta_jogo` — ver 2.1) tem seu próprio contador de versão, armazenado em `personagens.versoes` (ver 2.12).
2. Toda mutação enviada pelo cliente (via WebSocket ou API REST) inclui a **seção alterada** e a **versão que o cliente tinha em mãos** quando começou a editar.
3. O servidor compara a versão recebida com a versão atual daquela seção no banco:
   - **Bate:** a escrita é aplicada, a versão da seção é incrementada, o novo estado é persistido e transmitido via WebSocket a todos os clientes conectados àquela ficha.
   - **Não bate (conflito):** a escrita é rejeitada (não aplicada), o servidor responde com a versão e o conteúdo atuais da seção; nenhum dado de ninguém é perdido silenciosamente.
4. O cliente que teve a escrita rejeitada descarta sua alteração otimista local, mostra a versão atual da seção e informa "Esta seção foi alterada por outra pessoa enquanto você editava — sua alteração não foi salva", permitindo tentar de novo sobre o estado atualizado.
5. **Override do Narrador:** o Narrador pode forçar a escrita mesmo em conflito (consistente com sua autoridade final, já estabelecida no ADR-001 e ADR-006), mas apenas via uma ação explícita ("Sobrescrever"), nunca como comportamento padrão — evita que uma escrita de Narrador apague silenciosamente uma edição concorrente do Jogador sem que isso seja uma decisão visível e deliberada.

**Por que granularidade de seção (não o documento inteiro):** o Narrador e o Jogador raramente editam a mesma seção ao mesmo tempo — granularidade de seção deixa que edições em seções diferentes (ex.: Narrador em `estado`, Jogador em `habilidades`) nunca conflitem entre si, reduzindo falsos conflitos que uma versão única para a ficha inteira geraria.

**Por que OCC e não CRDT/Operational Transformation:** CRDT e OT resolvem bem edição colaborativa de texto livre (onde existe uma função de merge natural, caractere a caractere). A ficha é dados estruturados de regras de jogo (um número de Atributo, uma lista de Disciplinas) — não há uma função de merge sensata para "Força 3" e "Força 4" editados ao mesmo tempo; a única resposta correta é perguntar a um humano qual valor vale. OCC com rejeição explícita faz exatamente isso, com uma fração da complexidade de implementação de um CRDT.

**Por que OCC e não lock pessimista (travar a seção durante edição):** exigiria gerenciar aquisição/liberação/timeout de lock e bloquearia o Jogador de editar `habilidades` só porque o Narrador está com `estado` "aberto" em outra aba — contraria o objetivo de tempo real como cidadão de primeira classe (ADR-001, princípio 4).

**Consequência para o histórico (2.12):** como a granularidade de conflito é por seção, o histórico também passa a registrar apenas a seção alterada e sua versão a cada mudança (`personagens_historico`, ver 2.12), não mais o documento inteiro a cada escrita — endereça o risco de *write amplification* identificado na revisão arquitetural, já que a maioria das edições toca uma seção pequena da ficha, não a ficha inteira.

## 3. Consequências

### 3.1. Positivas

- **Completude:** A ficha modela todos os aspectos do Capítulo Três, garantindo fidelidade ao material original.
- **Automação:** Regras como Fraquezas de Clã, custo de experiência e limites de Geração são aplicadas automaticamente.
- **Colaboração:** A ficha é sincronizada em tempo real, facilitando a colaboração entre jogador e Narrador.
- **Flexibilidade:** A estrutura JSONB permite consultas flexíveis e evolução do schema sem migrações complexas.
- **Extensibilidade:** Novas Habilidades, Disciplinas ou Antecedentes podem ser adicionados facilmente.
- **Histórico:** O versionamento permite rastrear a evolução do personagem ao longo da crônica.

### 3.2. Negativas

- **Complexidade de Implementação:** Modelar todas as regras e validações é um esforço significativo.
- **Performance:** Fichas com muitos dados podem impactar a performance de sincronização. Otimizações serão necessárias.
- **Curva de Aprendizado:** Novos jogadores podem se sentir sobrecarregados com a complexidade da ficha. A UI deve guiar o processo.
- **Manutenção:** À medida que novas edições ou suplementos são lançados, a ficha precisa ser atualizada.
- **Consistência:** Garantir que a ficha esteja sempre consistente (ex: Humanidade = Consciência + Autocontrole) exige validações rigorosas.

### 3.3. Alternativas Descartadas

| Alternativa                               | Motivo da Rejeição                                                   |
| ----------------------------------------- | -------------------------------------------------------------------- |
| **Ficha em Tabelas Relacionais Puras**    | Muito rígida para a complexidade da ficha. JSONB é mais flexível.    |
| **Ficha em Arquivo Local (sem servidor)** | Não permite colaboração em tempo real.                               |
| **Ficha Simplificada**                    | Perderia a riqueza do sistema de Vampiro.                            |
| **Sem Versionamento**                     | Impossibilitaria rastrear a evolução do personagem e reverter erros. |
| **Sem Automação de Regras**               | Sobrecarregaria o jogador e o Narrador com cálculos manuais.         |
