## 1. Contexto

O **Capítulo Quatro: Disciplinas** é o coração do poder sobrenatural em *Vampiro: A Máscara*. As Disciplinas são os poderes místicos concedidos pelo Abraço, que separam os vampiros dos mortais e definem o que cada personagem é capaz de fazer. Elas são a principal forma de customização mecânica e a fonte de grande parte das interações táticas e narrativas do jogo.

O capítulo define:
- **17 Disciplinas Principais** (Animalismo, Auspícios, Demência, Dominação, Fortitude, Metamorfose, Necromancia, Ofuscação, Potência, Presença, Quietus, Quimerismo, Rapidez, Serpentis, Taumaturgia, Tenebrosidade, Vicissitude).
- **Poderes de Nível 1 a 5** (e além, para anciões).
- **Disciplinas com Linhas e Rituais** (Necromancia e Taumaturgia).
- **Mecânicas Específicas** (gasto de sangue, testes resistidos, efeitos de longa duração).
- **Interações entre Disciplinas** (ex: Auspícios vs. Ofuscação; Fortitude vs. dano agravado).

A plataforma precisa modelar as Disciplinas não como **texto estático**, mas como um **motor dinâmico** que:
- Aplique automaticamente os efeitos dos poderes.
- Calcule custos (sangue, Força de Vontade).
- Resolva testes resistidos.
- Gerencie durações e condições.
- Permita a extensibilidade (novos poderes, linhagens, níveis anciões).

Este ADR define **como modelar e executar as Disciplinas** na plataforma, estabelecendo as bases para o Motor de Resolução de Ações (ADR-006) e os Sistemas Dramáticos (ADR-007).

## 2. Decisão

Decidimos modelar as Disciplinas através de **sete pilares fundamentais**, cada um representando um aspecto do Capítulo Quatro.

### 2.1. Modelagem Geral de Disciplinas

**Decisão:** Cada Disciplina é uma **entidade de dados** com metadados, poderes e regras associadas.

**Estrutura de Dados:**

├── id: UUID
├── nome: string                        # Ex: "Animalismo", "Taumaturgia"
├── tipo: enum                          # Padrão | Linha | Ritual | Contramagia

├── clãs_associados: [UUID]             # Clãs que possuem esta Disciplina
├── custo_sangue: bool                  # Se os poderes exigem gasto de sangue
├── custo_forca_vontade: bool           # Se os poderes exigem gasto de Força de Vontade

├── resistido: bool                     # Se os poderes são resistidos por outro personagem
├── atributo_resistencia: string        # Ex: "Força de Vontade", "Vigor + Fortitude"

├── rituais: [Ritual]                   # Para Necromancia e Taumaturgia

### 2.2. Modelagem de Poderes

**Decisão:** Cada poder de Disciplina é uma **entidade de dados** com efeitos mecânicos, custos e condições.

**Estrutura de Dados:**

```
Poder (Power)
├── id: UUID
├── disciplina: UUID                    # Referência à Disciplina
├── nivel: int                          # Nível (1-5+)
├── nome: string                        # Ex: "Sussurros Selvagens", "Olhos da Besta"
├── descrição: text                     # Efeito narrativo
├── sistema: text                       # Regras mecânicas
├── custo: Custo                        # Custos para ativar
│   ├── sangue: int                     # Pontos de sangue gastos
│   ├── forca_vontade: int              # Pontos de Força de Vontade gastos
│   └── outros: string                  # Outros custos (ex: "1 ponto de Força de Vontade permanente")
├── tipo_acao: enum                     # Reflexiva | Padrão | Estendida
├── duração: Duração                    # Quanto tempo dura o efeito
│   ├── tipo: enum                      # Instantânea | Turno | Cena | Noite | Permanente
│   └── valor: string                   # Ex: "1 turno por sucesso"
├── alcance: string                     # Ex: "Contato visual", "50 jardas", "Toque"
├── alvo: enum                          # Próprio | Um Alvo | Múltiplos Alvos | Área

├── atributo_resistencia: string        # Ex: "Força de Vontade", "Vigor + Fortitude"
├── efeitos: [Efeito]                   # Lista de efeitos mecânicos
│   ├── tipo: enum                      # Dano | Condição | Bônus | Penalidade | Controle
│   ├── valor: string                   # Ex: "1 nível de dano agravado por sucesso"
│   └── condição: string                # Ex: "Se o alvo falhar no teste"
├── pré-requisitos: [Pré-Requisito]     # Ex: "Nível 3 em Animalismo"

### 2.3. Modelagem de Linhas (Necromancia e Taumaturgia)

**Decisão:** Necromancia e Taumaturgia são modeladas como **Disciplinas com Linhas**, cada uma com suas próprias regras de progressão.

**Estrutura de Dados:**

```
Linha (Path)
├── id: UUID
├── disciplina: UUID                    # Referência à Disciplina (Necromancia ou Taumaturgia)
├── nome: string                        # Ex: "Linha do Sepulcro", "Linha do Sangue"
├── tipo: enum                          # Primária | Secundária
├── descrição: text                     # Visão geral da Linha
├── poderes: [Poder]                    # Poderes da Linha (níveis 1 a 5)
├── rituais: [Ritual]                   # Rituais associados
└── regras_especiais: [Regra]           # Regras específicas (ex: progressão)
```

**Regras de Progressão (Necromancia):**

- O personagem deve ter pelo menos **3 níveis na Linha Primária** antes de aprender uma Linha Secundária.
- Deve dominar a **Linha Primária (5 níveis)** antes de aprender uma **Terceira Linha**.
- O avanço na Linha Primária custa o valor normal de experiência.
- O estudo de novas Linhas custa **7 pontos de experiência** (custo de "Nova Disciplina").

**Regras de Progressão (Taumaturgia):**

- O personagem escolhe uma **Linha Primária** ao aprender Taumaturgia.
- A Linha Primária aumenta automaticamente com o nível de Taumaturgia.
- Linhas Secundárias podem ser aprendidas após **2 níveis na Linha Primária**.
- O nível da Linha Primária deve estar sempre **pelo menos 1 ponto acima** de qualquer Linha Secundária.
- Após dominar a Linha Primária (5 níveis), as Linhas Secundárias podem ser elevadas até este nível.

| **Taumaturgia** | Linha do Sangue (Primária), Controle de Elementais, Linha da Natureza, Mãos da Destruição, Sedução das Chamas, Poder de Netuno, Movimento da Mente, Linha da Conjuração, Linha da Corrupção, Linha de Marte, Linha da Tecnomancia, Linha da Vingança Paterna, Controle Climático |

### 2.5. Execução de Poderes (O Motor de Disciplinas)

**Decisão:** Implementar um **Motor de Disciplinas** no backend que executa os poderes, aplicando custos, resolvendo testes e aplicando efeitos.

**Fluxo de Execução:**

```
1. Jogador declara uso de poder
   ├── Seleciona a Disciplina e o Poder
   ├── Seleciona o(s) alvo(s)
   └── Confirma o uso

2. Motor de Disciplinas valida o uso
   ├── Verifica se o personagem tem o nível necessário
   ├── Verifica se há custos a pagar (sangue, Força de Vontade)
   ├── Verifica pré-requisitos (ex: contato visual)
   └── Verifica se o alvo é válido

3. Motor de Disciplinas aplica custos
   ├── Deduz pontos de sangue
   ├── Deduz pontos de Força de Vontade
   └── Aplica outros custos (ex: Força de Vontade permanente)

4. Motor de Disciplinas resolve o teste (se aplicável)
   ├── Calcula a parada de dados (Atributo + Habilidade)
   ├── Determina a dificuldade
   ├── Rola os dados
   └── Conta os sucessos

5. Motor de Disciplinas aplica efeitos
   ├── Aplica dano (se aplicável)
   ├── Aplica condições (ex: frenesi, paralisia)
   ├── Aplica bônus/penalidades (ex: +2 em Força)
   └── Registra a duração do efeito

6. Motor de Disciplinas notifica os envolvidos
   ├── Notifica o Narrador (se necessário)
   ├── Notifica o(s) alvo(s) (se aplicável)
   └── Registra no log da sessão

7. Motor de Disciplinas atualiza o estado
   ├── Atualiza a ficha do usuário
   ├── Atualiza a ficha do(s) alvo(s) (se aplicável)
   └── Agenda a expiração do efeito (se aplicável)
```

**Exemplo de Execução (Dominação 1 — O Comando):**

```
1. Jogador (Ventrue) declara uso de "O Comando" em um mortal.
2. Motor valida: O personagem tem Dominação 1, o alvo está no campo de visão.
3. Motor aplica custos: Nenhum custo de sangue ou Força de Vontade.
4. Motor resolve o teste: Manipulação + Intimidação (dificuldade = Força de Vontade atual do alvo).
5. Motor rola os dados: 3 sucessos.
6. Motor aplica efeitos: O alvo obedece ao comando de uma palavra ("Corra!").
7. Motor notifica: O Narrador vê o resultado no painel; o alvo vê a notificação "Você foi dominado a correr".
8. Motor atualiza o estado: O alvo é marcado com a condição "Dominado" por 1 turno.
```

### 2.6. Interações entre Disciplinas

**Decisão:** Implementar um **sistema de interações** entre Disciplinas, resolvendo conflitos de forma automática.

**Interações Conhecidas:**

| Disciplina A | Disciplina B | Interação |
|--------------|--------------|-----------|
| **Auspícios** | **Ofuscação** | Auspícios pode detectar Ofuscação se o nível de Auspícios > Ofuscação (ver quadro "Vendo o Invisível", p. 142). |
| **Auspícios** | **Quimerismo** | Auspícios pode perfurar ilusões de Quimerismo. |
| **Fortitude** | **Dano Agravado** | Fortitude permite absorver dano agravado. |
| **Potência** | **Fortitude** | Potência aumenta o dano; Fortitude absorve. |
| **Rapidez** | **Rapidez** | Personagens com Rapidez podem realizar ações múltiplas. |
| **Dominação** | **Geração** | Um vampiro não pode Dominar outro de Geração inferior. |
| **Presença** | **Força de Vontade** | O alvo pode gastar Força de Vontade para resistir. |
| **Taumaturgia** | **Contramagia** | Contramagia Taumatúrgica pode anular poderes de Taumaturgia. |
| **Necromancia** | **Auspícios** | Necromancia pode ser detectada por Auspícios. |
| **Vicissitude** | **Fortitude** | Vicissitude causa dano agravado; Fortitude absorve. |

**Motor de Interações:**

```
Interação (Interaction)
├── id: UUID
├── disciplina_a: UUID
├── disciplina_b: UUID
├── tipo: enum                          # Detecção | Resistência | Anulação | Bônus
├── regra: text                         # Descrição da regra
├── resolução: enum                     # Teste Resistido | Comparação de Níveis | Gasto de Força de Vontade
└── efeito: string                      # O que acontece se A vencer
```

**Exemplo de Resolução (Auspícios vs. Ofuscação):**

```
1. Personagem A usa Auspícios para detectar Personagem B (Ofuscado).
2. Motor compara os níveis: Auspícios 3 vs. Ofuscação 2.
3. Motor determina: Auspícios > Ofuscação, então A pode detectar B.
4. Motor solicita um teste de Percepção + Acuidade (dificuldade 7 - (Auspícios - Ofuscação)).
5. Motor rola os dados e aplica o resultado.
```

### 2.7. Disciplinas Avançadas (Nível 6+)

**Decisão:** Implementar **Disciplinas Avançadas** para personagens de Geração 7 ou inferior.

**Regras:**

- Personagens de Geração 7 ou inferior podem ter Disciplinas acima de 5.
- Cada nível acima de 5 concede **poderes alternativos** ou **aprimoramentos** dos poderes existentes.
- O custo de experiência para Disciplinas acima de 5 é o dobro do normal.
- Apenas personagens de Geração 6 ou inferior podem ter Disciplinas acima de 6.
- Apenas personagens de Geração 5 ou inferior podem ter Disciplinas acima de 7.

### 2.8. Extensibilidade: Novas Disciplinas e Poderes

**Decisão:** A plataforma deve ser **extensível**, permitindo que o Narrador crie novas Disciplinas, Linhas, Rituais e Poderes.

**Funcionalidades:**

- **Editor de Disciplinas:** O Narrador pode criar Disciplinas customizadas, definindo:
  - Nome, descrição, tipo.
  - Clãs associados.
  - Poderes (de templates ou customizados).
  - Regras especiais.
- **Editor de Poderes:** O Narrador pode criar Poderes customizados, definindo:
  - Nome, nível, descrição.
  - Custos (sangue, Força de Vontade).
  - Tipo de ação, duração, alcance.
  - Efeitos mecânicos (dano, condições, bônus).
  - Pré-requisitos.
- **Editor de Linhas:** O Narrador pode criar Linhas customizadas para Necromancia e Taumaturgia.
- **Editor de Rituais:** O Narrador pode criar Rituais customizados, definindo:
  - Nome, nível, descrição.
  - Ingredientes, tempo de execução.
  - Efeitos mecânicos.
- **Importação/Exportação:** As criações customizadas podem ser exportadas (JSON) e compartilhadas.
- **Marketplace (Opcional):** No futuro, um marketplace para compartilhar Disciplinas customizadas.

### 2.9. Interface de Usuário para Disciplinas

**Decisão:** Implementar uma **interface intuitiva** para o uso de Disciplinas, que guie o jogador e mostre os resultados.

**Componentes da UI:**

1. **Painel de Disciplinas:**
   - Lista todas as Disciplinas do personagem.
   - Mostra o nível de cada Disciplina.
   - Permite expandir para ver os poderes disponíveis.
   - Indica quais poderes estão ativos.

2. **Botão de Uso de Poder:**
   - Cada poder tem um botão "Usar".
   - Ao clicar, abre um modal de confirmação com:
     - Custo (sangue, Força de Vontade).
     - Alvo(s) (se aplicável).

### 2.10. Log e Auditoria de Disciplinas

**Decisão:** Todas as utilizações de Disciplinas são **registradas em log**, para auditoria e narrativa.

**Estrutura de Dados:**

```
LogDisciplina (DisciplineLog)
├── id: UUID
├── sessao: UUID                        # Referência à sessão
├── personagem: UUID                    # Quem usou
├── disciplina: UUID                    # Qual Disciplina
├── poder: UUID                         # Qual poder
├── alvo: UUID                          # Quem foi o alvo (se aplicável)
├── custo: Custo                        # Custos pagos
├── resultado: Resultado                # Sucessos, falhas, etc.
├── efeitos: [Efeito]                   # Efeitos aplicados
├── data: datetime                      # Quando ocorreu
└── notas: text                         # Notas do Narrador
```

**Funcionalidades:**

- **Auditoria:** O Narrador pode revisar todas as utilizações de Disciplinas.
- **Narrativa:** O log pode ser usado para criar uma "crônica" automática dos eventos.
- **Debug:** Em caso de bugs, o log ajuda a rastrear o que aconteceu.
- **Privacidade:** O log é visível apenas ao Narrador e ao jogador (conforme configuração).

## 3. Consequências

### 3.1. Positivas

- **Fidelidade ao Material Original:** Todas as Disciplinas e Poderes são modelados com suas mecânicas completas.
- **Automação:** Custos, testes e efeitos são aplicados automaticamente, reduzindo a carga cognitiva.
- **Interatividade:** A UI guia o jogador no uso de poderes, tornando o jogo mais acessível.
- **Interações:** O sistema resolve automaticamente conflitos entre Disciplinas (ex: Auspícios vs. Ofuscação).
- **Extensibilidade:** O Narrador pode criar novas Disciplinas, Linhas, Rituais e Poderes.
- **Auditoria:** O log de Disciplinas permite rastrear tudo que aconteceu na crônica.
- **Base para ADRs Futuros:** O Motor de Disciplinas estabelece as fundações para o Motor de Resolução de Ações (ADR-006) e os Sistemas Dramáticos (ADR-007).

### 3.2. Negativas

- **Complexidade de Implementação:** Modelar 17 Disciplinas, dezenas de Linhas e centenas de Poderes é um esforço massivo.
- **Balanceamento:** Garantir que todas as Disciplinas sejam equilibradas é um desafio de design.
- **Performance:** A execução de poderes em tempo real pode impactar a performance. Otimizações serão necessárias.
- **Curva de Aprendizado:** Novos jogadores podem se sentir sobrecarregados com tantas opções. A UI deve guiar o processo.
